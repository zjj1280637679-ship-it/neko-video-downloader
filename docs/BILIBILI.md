# B站普通投稿适配

2.4.0 复用已安装的羊魔本机内核，增加 B站普通投稿的当前分P。使用范围与实际验收结果分别记录，解析器存在不代表所有页面都能下载。

## 使用范围

- `bilibili.com`、`www.bilibili.com`、`m.bilibili.com` 的 `/video/BV…/` 和 `/video/av…/`，以及相同视频的 `/zh-Hans/video/`、`/zh-Hant/video/` 语言路径。
- 以当前地址的 `p=N` 选择分P。没有 `p` 时按 P1；规范地址总是保留 `?p=1`，与缺省地址去重。重复、非法或越界的分P拒绝处理，不默默回到 P1。
- 浏览器打开 b23 分享短链并跳转到上述视频页后可识别；本机不接收任意短链地址。
- 本轮不处理番剧、课程、直播、合集批量和交互式多视频。非单一完整视频结果不能覆盖成一个文件并报告成功。

## 下载行为

B站常见 DASH 音轨与画面轨是各自完整的 HTTP 文件；内核按正常方式下载、合并。它们不会因为使用 DASH 名称而被标成分片任务，也不为了让滑块生效强行切片。真正的 HLS/DASH 分片仍使用现有实时并发调度器。

最终成品与当前分P的标题、时长对应。实际清晰度来自下载格式/成品，不保证与浏览器当前选中的画质一致。缺少高画质时使用实际可获取格式；会员或充电试看不能冒充完整视频。合并与校验完成后交给 Chrome 默认目录，只有 Chrome 确认完成才显示已保存。

## 会话与访问条件

打开来源卡会自动验证当前分 P。内核与实际下载共用选轨规则和请求头，对所选媒体文件发起 GET，只读取开头的 32 字节，核对响应范围、可用长度以及媒体文件头。双轨视频需要分别验证画面和声音。单次结果有效 60 秒，切换分 P 后单独验证。预检不会创建下载任务。下载阶段仍会对成品做完整性校验。

默认匿名。仅在用户主动点击本站授权重试时，读取 `bilibili.com` / `.bilibili.com` 的必要会话，临时交给本机内核；不会读取 YouTube Cookie，也不写 Cookie 文件、配置或日志。Chrome 已有可选 Cookie 权限不等于同意所有站点自动使用登录状态。

412、访问验证、地区限制、会员权限和来源失效分别是站点返回的访问条件。授权不能保证消除风控；网页本身也返回 412 时，不将它错误描述成分片下载故障。

## 安装与验证

更新扩展到 2.4.0 后，还需使用同版本 `scripts/install-native.ps1` 更新本机主机；已安装的 Python/FFmpeg/Node 可复用。旧版只支持 YouTube 的主机会在读取 B站 Cookie 之前被能力检查拒绝。详见 [本机内核安装](YOUTUBE.md)。
