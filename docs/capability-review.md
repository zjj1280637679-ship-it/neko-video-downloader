# 基本能力：计算、判断与可用路径

本项目的复查原则：**函数依据输入关系计算结果，判断依据证据选择处理路径。** 不能用固定加减代替反馈计算，也不能把“尚未确认”“一种方法失败”“存在多个候选”直接等同于“整个功能不可用”。

## 计算保留输入关系

并发控制的输入是实际并发 N 与总下载速度 V 的有效历史。对不同速度响应曲线，控制器应产生不同的探测与收敛过程。完成、失败和重试的次数不直接决定目标并发。

整数取整、采样时窗、测量容差与缓存水位各有明确作用；它们不能替代优化函数。缓存水位控制执行积压，采样资格防止被写盘或尾段干扰的数据进入曲线，均不直接重写目标并发。见[自适应并发说明](adaptive-download.md)。

## 判断保留条件与候选

媒体类型、播放器关联、清单处理和命令结果需要分别判断：

| 能力 | 判断依据 | 必须保留的处理路径 |
|---|---|---|
| 媒体识别 | 实际响应类型、视频元素来源、地址与页面提示 | 更强的新证据可以修正初始猜测；弱线路提示不覆盖明确文件格式，结果不应由消息先后顺序决定 |
| 分片识别 | 媒体类型、明确分片格式、DOM 播放证据、路径线索 | `part`、`chunk`、`hls` 目录名不能单独抹掉完整视频；被归类的记录应可被新证据纠正 |
| 播放器抓拍 | 明确的视频、文档与 frame 身份 | 唯一相关目标可直接使用；多个目标提供选择；目标失败保留该目标的错误，不换成无关视频 |
| 截图入口 | 已发现的播放器及其画面 | 没有可下载 URL 时，仍应能对 blob 或 srcObject 播放器尝试抓拍并读取已存原图 |
| HLS 密钥 | 当前分片适用的各 KEYFORMAT、METHOD 与密钥数据 | 未实现的一种格式不遮蔽同段已有的可用格式；真正无可用解密路径时说明具体条件 |
| HLS 初始化段 | 地址、字节范围、密钥、IV 与容器证据 | 同地址不同范围或加密状态分别处理；初始化段和正文各按其上下文解密与保存 |
| 清单地址 | HTTP 返回的实际最终地址 | 重定向后的相对分片、密钥、初始化段和子清单按最终地址解析 |
| 画质候选 | 有效清单、已列出的变体、码率与实际解析结果 | 优先高质量；收到登录 HTML 等无效清单时明确识别，准备失败后尝试其他已有候选，并展示实际选择及失败原因 |
| 浏览器目标 | 请求字段是否省略、目标是否合法、选择是否成功 | 只有省略字段可用已确认目标；选择失败不提交新目标；多步动作始终绑定同一目标 |
| 命令结果 | HTTP 状态、严格布尔结果、原始 CDP 返回 | 不能把字符串 `"false"` 或 HTTP 错误响应当成功；应用层结果保留原始信息供调用方核验 |

功能条件彼此独立。截图能力不依赖下载地址是否存在；通用 CDP 调用不依赖可视画面是否成功传输；某个画质或某种密钥格式不可用，不代表同一清单中的其他路径不可用。

## 对无法继续的情况给出具体结果

无法执行时，应说明是在什么目标、什么条件、哪一步失败，以及已有的替代路径。例如：给出清单中其他可用档位；提供明确播放器选择；保留原始清单和独立音轨地址；返回缺少 IV 或目标已关闭等具体原因。

未实现的样本解密或音视频混流不能通过忽略标签、输出密文、拼接不兼容数据或误报成功来代替。来源不明的图片也不能冒充用户选择的视频。接口鉴权和浏览器原有访问边界仍按其真实条件处理。

## 验收检查实际动作

测试同时覆盖“应当能做”“应当选择另一条已有路径”“确实无法完成时说明原因”，不以按钮变灰、分支不报错或返回非空结果作为能力正确的证明。

- 改变输入速度曲线，检查实际请求数随函数目标变化；分片未结束时仍能测速。
- 调换 DOM 与响应头事件顺序，检查最终媒体类型、文件后缀和下载入口一致。
- 给同一加密段提供可用与未知两种格式，检查实际解密后输出字节。
- 在同 URL 下变更初始化范围、密钥或 IV，检查输出包含正确初始化内容。
- 让最高候选失败、次级候选成功，检查真实请求、实际选档、音轨归属与提示。
- 在目标失败或界面切换期间，检查命令最终发往哪个文档或标签，而不只检查返回 `success`。
- 对只有播放器而无下载地址的页面，执行真实 popup 脚本中的抓拍、原图读取与保存动作。
- 对 HTTP 状态与 JSON 字段相互矛盾的响应，检查 CLI 输出和退出码。

测试结果与真实浏览器验证边界集中记录在[验证记录](validation.md)。

## 协议依据

- [RFC 8216：HLS](https://www.rfc-editor.org/rfc/rfc8216.html)，尤其 3.2、4.3.2.4、4.3.2.5 与 6.3.6：同段可提供多种密钥格式；初始化段具有独立范围和加密上下文。
- [Chrome webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest)：请求阶段与响应头阶段提供的证据不同，不能将早期推测固定为最终类型。
- [Chrome DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/)：目标、会话、参数和协议结果应保持明确。
