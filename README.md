# 羊魔 · 视频收藏 2.4.5

一个极简、粉紫动漫风格的 Chrome 视频下载扩展。顶部、空状态、进度条与扩展图标统一使用用户提供的黑白发羊角角色。进度条角色跟随真实进度轻轻浮动，取消或结束后静止；装饰不拦截点击，并支持系统减少动态效果。右上角提供大号“重新读取视频来源”按钮；移除当前网页信息栏、网页标题播报、画面抓拍与搜索框。“视频来源”页只负责发现与开始下载；进入“下载任务”页才显示分片并发滑条和保存位置。视频统一保存到 Chrome 默认下载目录，没有子文件夹、另存位置或设置弹窗。下载时显示速度和预计剩余时间；数据不足时显示“估算中”。

本版优先适配 ikanbot 的当前选中线路：页面可用 `blob:` 播放，扩展从线路数据与网络响应获取真实 HLS 清单。DOM 只采集选中线路，不把整页剧集全部列为下载候选；网络观察可以补充其他来源，同页换源后仍可能保留旧候选，以当前线路标记区分。

打开 B 站普通投稿的来源卡后，羊魔按当前分 P 匿名解析并试读选中的媒体轨。2.4.5 的下载按钮在等待时显示“正在验证…”和转圈图标，通过后变成实心的“立即下载”。点击后可看到“正在创建任务…”。结果在一分钟内有效，失败或过期可在卡片上重新验证。本版沿用 2.4.4 的本机内核。

2.3.0 增加 YouTube 页面识别及独立本机下载内核：来源页直接识别当前视频，不要求先嗅探出媒体直链。下载由 yt-dlp 解析格式，本机获取轨道并用 FFmpeg 合并，最终仍交给 Chrome 保存到默认目录。首次需要安装配套内核，详见 [YouTube 安装与使用](docs/YOUTUBE.md)。原 HLS 和直链流程保留；分片任务实时响应滑块，非分片任务正常下载。YouTube 仍可能要求登录验证，不能保证所有视频、网络或受限内容都可下载。

2.4.0 增加哔哩哔哩普通投稿适配：BV/av 地址按当前 `p` 分P识别，缺省按 P1；音视频分别下载后合并。站点身份、任务执行器和可选会话域统一由站点注册表管理，B站授权不会使用 YouTube Cookie。B站的 DASH 双轨常为两个完整 HTTP 文件，这种任务不受分片滑块影响。详见 [B站范围与验收](docs/BILIBILI.md)。

2.2.1修复冷启动与扩展更新后已有网页未重新识别的问题：打开弹窗或点击右上角重新读取，会重新连接并扫描当前可访问的页面框架，不刷新整个网页。来源扫描、任务恢复和偏好读取独立启动；同页报告等待必要的身份与标题确认后提交，发送失败可再次补报。普通轮询只读结果，不重复安装观察器。

滑动条选择 **1–375 路分片并发，默认64**，左“稳”、右“急”，自动保存，重新打开仍是上次的位置。2.2.0 将它改为全局实时控制：正在执行与排队的分片任务都使用最新值，调高立即补位，调低让已发出的分片自然完成，再按新上限补位。HLS任务仍逐个执行；直链交给Chrome管理。没有自动探测、升降档或按速度改并发的算法。这个数值表示同时处理的分片任务，不修改视频清单的分片总数，也不代表同样数量的TCP连接；实际请求受剩余分片、浏览器调度、重试等待和缓冲空间影响。

## 安装与使用

主分支提供已推送版本的构建。登录 GitHub 后，在 [构建记录](https://github.com/zjj1280637679-ship-it/neko-video-downloader/actions/workflows/check.yml?query=branch%3Amain) 中打开所需版本的成功运行，从 **Artifacts** 下载 `yangmo-extension`。也可以在源码根目录运行 `npm run package` 打包当前源码。

1. 解压构建产物，在 Chrome 打开 `chrome://extensions`。自行打包时，使用生成的 `dist/yangmo-2.4.5` 目录。
2. 打开开发者模式，选择“加载已解压的扩展程序”，选择**包含 manifest.json 的目录**。
3. 在视频网页选中线路并播放，打开羊魔，点击“下载视频”。
4. “下载任务”查看进度、调整并发；弹窗关闭后，后台任务继续。只有 Chrome 确认完成，才显示“已保存”。
5. 运行中的任务可“取消任务”；已保存、中断或已取消的任务可“删除任务”。删除会清理该任务的临时缓存和扩展列表记录，已保存文件仍留在磁盘上。

构建产物包含 `native/` 和内核安装脚本。使用 YouTube 或 B 站功能时，按 [本机内核安装与升级](docs/YOUTUBE.md) 将内核绑定到当前扩展 ID。已有配套依赖可复用。

已有 1.x 用户建议先保留旧目录，加载新版试用。不同目录可能产生不同扩展 ID，缓存不会自动跨 ID 迁移；同 ID 更新会尝试读取旧设置/任务记录。合法的整数并发值1–375保留，缺失或非法值恢复64。旧模式、子文件夹和保存询问字段不再控制行为；新下载与继续下载都使用 Chrome 默认目录。不要同时用两个版本下载同一视频。

## 能力与边界

| 类型 | 本版行为 |
|---|---|
| HTTP(S) 视频直链 | 交给 Chrome 下载，进度与完成状态按 Chrome 对账 |
| YouTube 点播 | 识别页面后交给本机内核解析、下载与合并；安装内核后可使用，登录验证按实际反馈处理 |
| B站普通投稿 | BV/av 当前分P，独立音视频合并；访问限制和实际画质以来源响应为准 |
| 完整 HLS 点播 | 解析清单、变体、TS/fMP4、Byte Range、普通 identity AES-128；分片并行获取，按序写盘 |
| 中断的 HLS | 保留校验通过的分片；点击继续时重新核对清单和缓存，过期来源需重新获取 |
| 直播/缺失分片/不支持的加密 | 说明具体条件，不截断清单、不输出密文冒充视频 |
| 独立音视频轨 | YouTube 与 B站由本机内核合并；其他站点当前不混流，有完整候选时尝试候选，否则说明原因 |
| blob/MSE | 不将临时 blob 地址当成公网视频文件；继续寻找线路或网络清单 |

HLS 的 TS 输出保留 `.ts`；不会仅改后缀假装转成 MP4。来源允许访问、链接仍有效、格式在支持范围内，下载才可能成功；本版不声称支持所有网站。

新版可继续使用同一扩展 ID 下的旧版 HLS 分片缓存。回退到 2.4.0 后，该版本会重新下载仅由新版缓存的分片。

## 开发

扩展没有运行时第三方依赖，无打包器也能直接加载。开发检查需要 Node.js 20+。

```sh
npm run verify       # 入口/语法检查 + 全部回归测试
npm run package      # 打包扩展运行时与本机内核安装文件到 dist/yangmo-2.4.5
npm run preview      # http://127.0.0.1:4173，仅视觉模拟数据
```

预览支持 `?case=source`、`jobs`、`empty`、`error`、`platforms` 和 `platform-jobs`，仅使用模拟数据。角色资产来源见 [视觉规范](docs/VISUAL-DESIGN.md)。

## 权限与数据

`webRequest` 观察媒体响应，HTTP(S) 站点权限覆盖播放器与跨域 CDN；`downloads` 保存文件；`offscreen` 执行 HLS 合并；`storage` 保存任务与设置；`activeTab` 获取当前页；`scripting` 在已有站点授权范围内重新连接当前网页的本地扫描脚本。页面候选保存在 session，任务元数据在 local，已验证分片在 OPFS。扩展不加载远程脚本，无分析上报或外部解析服务器，不采集 Cookie 请求头。

YouTube 与 B站使用 `nativeMessaging` 和本机内核通信。默认匿名解析；只有用户主动点击当前站点的登录状态重试并授予可选 `cookies` 权限，才读取该站点根域的 Cookie（YouTube：`youtube.com`，B站：`bilibili.com`），临时交给本机内核请求此视频。来源域由已验证视频 URL 决定，消息不能指定任意 Cookie 域；不同站点不混用会话，不写入任务记录、日志或配置文件。已经授予权限也不会让普通下载自动读取 Cookie。可在 Chrome 中撤销可选权限。签名解析及挑战处理由独立内核及其已安装依赖执行，不在扩展页面执行远程代码。

连续嗅探目前仍需 HTTP(S) 站点范围权限；没有把 `activeTab` 误称为跨域 CDN 的完整授权。未来按站点授权需同时处理页面、嵌入框架和 CDN 权限，作为单独迁移设计。
