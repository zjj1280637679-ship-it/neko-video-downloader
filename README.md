# 喵喵视频下载姬 · Neko

一个保留樱花与猫咪风格的 Chrome Manifest V3 音视频下载扩展。在弹窗内选择视频、查看下载进度和管理保存设置；关闭弹窗后，后台任务继续运行。

## 安装与更新

需要 Chrome 116 或更新版本。

1. 下载并解压扩展包，保留解压目录。
2. 在 Chrome 地址栏手动输入 `chrome://extensions/`，开启开发者模式。
3. 选择“加载已解压的扩展程序”，选中含 `manifest.json` 的目录。
4. 更新已有安装时，先等待当前下载结束，再将新版文件放到原目录，点击扩展卡片的“重新加载”，确认版本为 1.4.1，再刷新视频页面。
5. 播放目标视频，点击工具栏中的“喵喵视频下载姬”。

`启动并测试插件.bat` 仅打开测试页面并显示安装步骤。Chrome 137 起，官方 Chrome 已不再支持通过 `--load-extension` 自动加载扩展。[Chrome 官方说明](https://developer.chrome.google.cn/blog/extension-news-june-2025?hl=en)。

## 下载与保存设置

- 在“视频来源”中点击下载，弹窗自动切换到“下载任务”，不会打开单独的下载页面。
- 普通文件交给 Chrome 下载；HLS 在隐藏的后台文档中解析、解密和合并，再交给 Chrome 保存。
- 可以关闭弹窗，重新打开后继续查看进度、取消或重试。只有 Chrome 确认文件保存完成后才显示“已保存”和“在文件夹中显示”。请保持 Chrome 运行；浏览器退出或扩展重载会中断尚未完成的 HLS 任务，重新下载即可。
- 默认直接保存到 **Chrome 默认下载文件夹**，不主动弹出位置选择框。重名文件由 Chrome 自动改名。
- 点弹窗右上角设置，可填写默认目录下的子文件夹，例如 `Videos/动画`；留空就是默认目录。也可开启“每次询问保存位置”。设置对之后的下载和截图生效。
- HLS 默认自动并行：从 2 路开始，根据并行数变化后的总下载速度尝试增减；总速持续提升就增加，收益趋平就停止增加，降速就尝试减少。即使每路速度下降，只要总速度增加仍可保留更多并行。设置也可切换为手动 1–8 路。
- 分片失败会连同内容校验、AES 解密一起自动重试，最多 6 次尝试。仍失败时，已存到临时磁盘的成功分片会保留，在“下载任务”点“继续下载”只补缺失或校验损坏的分片。
- 续传仅在本次浏览器会话内可用，保持 Chrome 运行，不要重载扩展。需要放弃时点“清除缓存”；成功保存或主动取消会清理本任务缓存。浏览器重启后，下次创建下载引擎时会清理已失去任务记录的自有缓存。
- “更改 Chrome 下载位置”打开 Chrome 的下载设置。这里修改的是浏览器的默认下载目录，也会影响其他 Chrome 下载。
- 切换集数或线路后，扩展识别当前选中的 `lineData.active`，不会把未播放的所有集数塞入列表。
- 弹窗区分“等待播放”“已播放，正在识别”和“已播放，暂未识别到可下载来源”。预加载来源可以直接下载，但不会据此声称视频已经播放；无法判断跨域播放器时显示未确认状态。
- 展开“当前网页画面”可抓拍当前帧。跨域播放器禁止读取画面时会明确提示，截图只在本地处理。

## v1.4.1：两种状态的猫咪循环动画

- 等待播放时，小猫轻轻探头、眨眼，播放气泡浮动提醒；正在识别时，小猫追随光点寻找视频。
- 同一状态下的列表轮询保留动画节点，让循环连贯播放。切换任务页签、打开弹层或页面隐藏时暂停动画。
- 动画仅作装饰，保留明确的状态文字；遵循系统的“减少动态效果”偏好，使用静态画面。不增加依赖或权限。

## v1.4.0：按总速度自动并行与播放状态

- 并行调整仅依据总下载速度与并行数的变化趋势，不依据单路平均速度。按实际经过时间统计成功下载并解密的分片字节，失败与退避耗时自然计入窗口，错误本身不会单独触发降并行。
- 每次尝试增减 1 路，采用至少 4 秒、4 个成功分片的测量窗口与 3% 噪声容差。增并行后总速度确有提升才保留；减少并行后总速度下降则撤回。冷却期用于减少反复抖动，1–8 路是资源上限，不是固定目标。
- 缓存复用和任务尾段不用于调节判断；短任务可能在形成足够样本前完成。弹窗显示合计有效速度、当前并行数及调整原因，停滞时速度会降至零。
- 根据实际播放事件和已播放区间判断播放状态，预加载和暂停状态下单纯拖动进度不算已播放。暂停保留播放记录，换源、刷新和离开子框架会清理旧状态。
- 播放后约 10 秒仍无可下载来源，结束持续识别提示；未知播放器保持明确的未确认状态。无需增加扩展权限。

自动并行会持续试探当前条件下的吞吐变化，不能保证找到所有网络条件下的最高速度，也不能替代分片重试与续传。

## v1.3.1：解密重试与分片续传

- 修复 v1.3.0 仅重试网络请求、AES 解密错误直接结束整项下载的问题。重新请求异常分片时绕过浏览器缓存，并安全刷新密钥。
- 每个资源共用最多 6 次尝试预算，采用有上限的指数退避，支持来源的 Retry-After；不把磁盘错误当网络错误重试。
- 将固定批次等待改为有界滑动并行，保持输出顺序和内存上限。
- 每片完成后保存独立检查点；继续下载核对清单签名、文件大小与 SHA-256，复用有效分片，只补缺失或损坏片。
- 弹窗增加继续下载、清除缓存、自动重试说明与并行数设置。继续任务保留原文件名和保存位置，采用当前并行设置。

v1.3.0 已在失败时清理的内容无法恢复；升级后第一次需要重新开始下载。

## v1.3.0 改进

- 移除独立下载工作台；下载、进度、取消、重试和保存设置均在弹窗中完成。
- 新增后台任务协调器与 offscreen 文档，下载生命周期不再依赖弹窗是否打开。
- HLS 优先写入浏览器专属临时磁盘（OPFS），完成 Chrome 保存后仅清理本任务临时文件；不把整个长视频堆在内存中。
- 任务恢复会对照后台引擎与 Chrome 实际状态；失联、保存中断和写盘失败不会显示成功。
- 处理重复点击、保存响应丢失、启动时取消与后台状态同步，避免重复下载和进度刷新循环。
- 默认使用 Chrome 下载目录，新增子文件夹和每次选择位置设置。
- 保留樱花色与猫咪风格，重新整理来源/任务标签、状态卡片、设置弹窗和键盘焦点。

继续包含 v1.2 的 HLS 修复：重定向相对路径、AES-128 IV、初始化段、字节范围、分片重试、有界并发和有序写入；以及捕获状态恢复、碎片过滤和安全文本渲染。

## 格式与限制

- 支持普通文件、有限长度的 HLS VOD、标准 AES-128 分片加密及兼容的 fMP4 初始化段与字节范围。
- TS 流保存为 `.ts`，fMP4 流保存为 `.mp4`；保留原始编码顺序拼接，不转码。
- DRM / SAMPLE-AES、直播、独立外置音轨或不能安全拼接的清单会明确报错，避免生成缺声或损坏文件。
- 某些站点依赖授权、请求头或短期链接。403 和过期链接会按实际错误报告；可刷新视频页后重试。
- 临时磁盘受浏览器配额和可用空间限制；分片缓存、合并文件与最终下载会增加磁盘占用。仅在 OPFS API 不支持时使用最多 256 MiB 的内存回退，此模式不提供分片续传；配额或写盘错误直接报错。
- 如果无法确认 Chrome 已结束读取，保留本次临时文件并显示清理提示，避免破坏仍在保存的文件。
- 同时最多安排 10 个任务，多个 HLS 视频依次处理，每个视频内的分片并行。保留最近 20 个结束任务；带缓存的中断任务保留到手动清理或会话结束。不支持跨浏览器重启的任务恢复。
- 截图受浏览器跨域画布规则限制。

## 开发验证

无构建步骤，扩展运行时不加载外部 JavaScript。Node.js 20+ 可运行：

```sh
npm test
```

测试覆盖捕获、HLS 核心、后台任务、offscreen 生命周期和弹窗交互。集成测试通过真实本地 HTTP/AES-128 分片，将同一套核心、任务协调器及 offscreen 引擎连接起来，并使用明确的 Chrome API 适配器验证文件保存与清理。

真实站点样本、浏览器预览和模拟 API 的验证边界分别见 `VALIDATION.md`。自动测试通过不等同于已安装扩展的真实 Chrome 端到端验收。

## 权限

`webRequest` 观察媒体响应；`downloads` 保存文件和追踪状态；`storage` 保存会话任务与本地设置；`activeTab` 获取当前页面信息；新增 `offscreen` 用于关闭弹窗后继续处理 HLS。`<all_urls>` 用于识别和请求不同站点的媒体，与 v1.2 相同。媒体记录和设置不上传到服务端。

仓库中的 `browser_controller.py` 是旧版独立远程调试实验，不属于扩展运行所需文件，发行包不包含它。常规使用无需启动控制台或开放调试端口。
