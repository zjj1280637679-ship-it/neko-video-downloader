# 羊魔 · 视频收藏 2.2.1

一个极简、粉紫动漫风格的 Chrome 视频下载扩展。顶部、空状态、进度条与扩展图标统一使用用户提供的黑白发羊角角色。进度条角色跟随真实进度轻轻浮动，取消或结束后静止；装饰不拦截点击，并支持系统减少动态效果。右上角提供大号“重新读取视频来源”按钮；移除当前网页信息栏、网页标题播报、画面抓拍与搜索框。“视频来源”页只负责发现与开始下载；进入“下载任务”页才显示分片并发滑条和保存位置。视频统一保存到 Chrome 默认下载目录，没有子文件夹、另存位置或设置弹窗。下载时显示速度和预计剩余时间；数据不足时显示“估算中”。

本版优先适配 ikanbot 的当前选中线路：页面可用 `blob:` 播放，扩展从线路数据与网络响应获取真实 HLS 清单。DOM 只采集选中线路，不把整页剧集全部列为下载候选；网络观察可以补充其他来源，同页换源后仍可能保留旧候选，以当前线路标记区分。

2.2.1修复冷启动与扩展更新后已有网页未重新识别的问题：打开弹窗或点击右上角重新读取，会重新连接并扫描当前可访问的页面框架，不刷新整个网页。来源扫描、任务恢复和偏好读取独立启动；同页报告等待必要的身份与标题确认后提交，发送失败可再次补报。普通轮询只读结果，不重复安装观察器。

滑动条选择 **1–375 路分片并发，默认64**，左“稳”、右“急”，自动保存，重新打开仍是上次的位置。2.2.0 将它改为全局实时控制：正在执行与排队的分片任务都使用最新值，调高立即补位，调低让已发出的分片自然完成，再按新上限补位。HLS任务仍逐个执行；直链交给Chrome管理。没有自动探测、升降档或按速度改并发的算法。这个数值表示同时处理的分片任务，不修改视频清单的分片总数，也不代表同样数量的TCP连接；实际请求受剩余分片、浏览器调度、重试等待和缓冲空间影响。

## 安装与使用

最新版本：[2.2.1 安装包](https://github.com/zjj1280637679-ship-it/neko-video-downloader/releases/download/v2.2.1/yangmo-video-downloader-2.2.1.zip) · [版本说明与校验文件](https://github.com/zjj1280637679-ship-it/neko-video-downloader/releases/tag/v2.2.1)

1. 下载并解压上面的扩展安装包（不是 GitHub 自动生成的 Source code），在 Chrome 打开 `chrome://extensions`。
2. 打开开发者模式，选择“加载已解压的扩展程序”，选择**包含 manifest.json 的目录**。
3. 在视频网页选中线路并播放，打开羊魔，点击“下载视频”。
4. “下载任务”查看进度、调整并发；弹窗关闭后，后台任务继续。只有 Chrome 确认完成，才显示“已保存”。
5. 运行中的任务可“取消任务”；已保存、中断或已取消的任务可“删除任务”。删除会清理该任务的临时缓存和扩展列表记录，已保存文件仍留在磁盘上。

已有 1.x 用户建议先保留旧目录，加载新版试用。不同目录可能产生不同扩展 ID，缓存不会自动跨 ID 迁移；同 ID 更新会尝试读取旧设置/任务记录。合法的整数并发值1–375保留，缺失或非法值恢复64。旧模式、子文件夹和保存询问字段不再控制行为；新下载与继续下载都使用 Chrome 默认目录。不要同时用两个版本下载同一视频。

## 能力与边界

| 类型 | 本版行为 |
|---|---|
| HTTP(S) 视频直链 | 交给 Chrome 下载，进度与完成状态按 Chrome 对账 |
| 完整 HLS 点播 | 解析清单、变体、TS/fMP4、Byte Range、普通 identity AES-128；分片并行获取，按序写盘 |
| 中断的 HLS | 保留校验通过的分片；点击继续时重新核对清单和缓存，过期来源需重新获取 |
| 直播/缺失分片/不支持的加密 | 说明具体条件，不截断清单、不输出密文冒充视频 |
| 独立音视频轨 | 当前不混流；有其他完整候选时尝试已列出的候选，否则说明原因 |
| blob/MSE | 不将临时 blob 地址当成公网视频文件；继续寻找线路或网络清单 |

HLS 的 TS 输出保留 `.ts`；不会仅改后缀假装转成 MP4。来源允许访问、链接仍有效、格式在支持范围内，下载才可能成功；本版不声称支持所有网站。

## 开发

扩展没有运行时第三方依赖，无打包器也能直接加载。开发检查需要 Node.js 20+。

```sh
npm run verify       # 入口/语法检查 + 全部回归测试
npm run package      # 仅打包运行时文件到 dist/yangmo-2.2.1
npm run preview      # http://127.0.0.1:4173，仅视觉模拟数据
```

预览支持 `?case=source`、`jobs`、`empty`、`error`，不执行实际下载。所有角色装饰与扩展图标共用一个本地透明 PNG；资产来源与提示词见 [视觉规范](docs/VISUAL-DESIGN.md)。

## 权限与数据

`webRequest` 观察媒体响应，HTTP(S) 站点权限覆盖播放器与跨域 CDN；`downloads` 保存文件；`offscreen` 执行 HLS 合并；`storage` 保存任务与设置；`activeTab` 获取当前页；`scripting` 在已有站点授权范围内重新连接当前网页的本地扫描脚本。页面候选保存在 session，任务元数据在 local，已验证分片在 OPFS。无分析上报、无外部后端、无远程脚本，也不收集 Cookie 请求头。

连续嗅探目前仍需 HTTP(S) 站点范围权限；没有把 `activeTab` 误称为跨域 CDN 的完整授权。未来按站点授权需同时处理页面、嵌入框架和 CDN 权限，作为单独迁移设计。
